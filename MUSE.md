# Muse Brain — MUSE.md, the map of the brain

This is a second brain: a plain folder of Markdown notes, built for
Muse. No Obsidian, no plugins, no external assets, no database.
Embeddings are optional and local-only (see ML below). One folder,
one map, one scan. Load this file first, then MAP.md.

Source pattern: Walrus X post, Nov 7 2026 (@walrus_systems) — a
Markdown folder turned into a living second brain. Adapted here:
Muse in for Claude, Obsidian out. See
`wiki/second-brain-pattern.md` and `docs/attribution.md`.

## Layout

- `MUSE.md` — this file. The only map. Under 200 lines by design.
- `MAP.md` — generated index. Regenerated by `scan.py`, never edited
  by hand.
- `MEMORY-MAP.md` — full memory map, generated by
  `scripts/memory-map.py`. Never edited by hand.
- `ml/` — local-first ML: TF-IDF/BM25, optional local embeddings.
- `dashboard.html` — generated simple dashboard from the same scan.
- `scan.py` — the one scan command. Stdlib only. Run: `python3 scan.py`
- `notes/` — atomic notes. One topic per file, kebab-case names.
- `raw/` — immutable sources. Never edited, never rewritten.
- `wiki/` — compiled synthesis. Muse-owned, updated on every ingest.
- `desk/` — working surface. Drafts and half-formed thinking.
- `daily/` — day pages.
- `memory.md` — durable facts, every claim with a source.
- `index.md` — hand catalog. `log.md` — append-only timeline.
- `rules/` — rules that load only on match. `skills/` — playbooks
  that run only when called. `templates/` — note templates.
- `README.md` — how the system works, how to add a note, how to scan.

## The three layers (Karpathy's llm.txt pattern)

1. `raw/` — immutable sources. Articles, files, links, transcripts.
   The source of truth.
2. `wiki/` — the compiled wiki. Summaries, entity pages, concept
   pages, synthesis. Updated on every ingest.
3. This map — the schema. How the brain is structured, what the
   conventions are, what to do on ingest / query / lint. It
   co-evolves with you over time.

Plus `notes/` (the living atomic layer), `desk/`, `daily/`,
`memory.md`, `index.md`, `log.md`.

## Load order (every session)

1. This file. Then `index.md` — the catalog. `MAP.md` is the
   generated link graph — read it, never edit it.
2. `memory.md` — only entries relevant to the task at hand.
3. `rules/people.md` — only when a person is involved.
4. `rules/writing.md` — only when writing or rewriting brain pages.
5. A `skills/` playbook — only when called (see below).

Never load the whole brain. The map tells you what to load.

## Tags

Every note carries 1–3 tags from this set, on its `Tags:` line:

`#brain` `#notes` `#projects` `#journal` `#people` `#places` `#ideas`
`#goals` `#money`

No other tags. If a note needs a new tag, the tag set changes here first.

## Links

Notes link to each other with `[[wiki-links]]` — `[[example-person]]`,
`[[example-project]]`. The scan resolves them against `notes/*.md`
and reports broken links and orphans in MAP.md. A note with no links
is a smell, not a crime; an inbox note is allowed to be unlinked.

## Rules — load only on match

- `rules/people.md` — how to write about people; loads on a person match.
- `rules/writing.md` — voice, format, and the no-slop bar; loads when
  writing or rewriting brain pages.
- If a rule contradicts this map, **the map wins**. Flag the conflict
  in `log.md` and propose a fix. (The Walrus post caught exactly this:
  a writing rule contradicting the map's naming rule.)

## Skills — run when called

Skills live in `skills/<name>/SKILL.md`. Each has a trigger phrase.
Say the phrase (or ask Muse to run it); Muse reads that skill file
and follows it. Skills never run uninvited.

| Skill | Trigger | Does |
|---|---|---|
| `ingest` | "brain: ingest <source>" | Raw → wiki, atomic notes, index + log |
| `search` | "brain: search <query>" | ripgrep + index first, then wiki pages |
| `ml-search` | "brain: ml search <query>" | TF-IDF/BM25 ranking, related, clusters, dups |
| `ask` | "brain: ask <question>" | Cited answer from wiki; file good answers back |
| `learn` | "brain: learn <correction>" | Turn a correction into a rule or memory entry |
| `rewrite` | "brain: rewrite <page>" | Tighten a page in your voice, keep sources |
| `weekly-review` | "brain: weekly review" | Stale check, orphans, conflicts, duplicates |
| `lint` | "brain: lint" | Contradictions, stale claims, missing links |
| `commit` | "brain: commit" | Status, diff review, commit + weekly summary |

Full command map: `docs/commands.md`.

## Memory rule (non-negotiable)

Every claim in `memory.md`, `wiki/`, and `notes/` carries a source:
a date plus who said it, or a file path. No source, no claim — write
`[source needed]` and put it on the weekly-review list instead of
inventing one. A second brain that can't say where a fact came from
turns into a confident liar. Corrections are first-class: the old
claim stays struck through with its source, the new claim gets the
new source. Never silently rewrite history.

## Atomic notes (one idea, one source, one conclusion)

`notes/` pages: one idea, one source, one conclusion, max 3 tags
from the set above, `Tags:` line at the end, `[[links]]` to related
notes. If a note needs a fourth tag or a second idea, split it.
Before filing a note, run `scripts/dup-check.py`: SHA-256 exact
match, then Jaccard similarity > 0.72 = likely duplicate — link to
the existing page instead of writing a new one.

## The five stages

CURATE → SEARCH → REWRITE → REVIEW → OBSERVE.
Curate sources in `raw/`; search the wiki before writing; rewrite
pages when new evidence lands; review weekly; observe via `log.md`
— every ingest, query, lint, and review gets one log line.

## Weekly loop (the dream pass, without the daemon)

Once a week, `weekly-review` runs: repeated corrections become
rules; stale people get flagged; unused rules get retired; `git diff`
gets a ≤200-word summary commit. Nothing here runs on a cron or a
server until you ask for it.

## The rules

1. **Sources under every claim.** A fact names where it came from:
   a date plus who said it, or a file path. No bare assertions.
2. **Grounded reasoning.** Work from your complete, actual data. When
   information is missing, name the gap instead of assuming. Never
   fill a gap with a population average or an invented fact.
3. **Balanced thinking.** Show both sides where they exist. Keep live
   tensions visible instead of resolving them quietly.
4. **Structured output.** Tight notes: what it is, key facts with
   sources, links to related notes. No filler, no questionnaires.
5. **Correct only what was corrected.** When you correct the record,
   fix only that item, name it explicitly, never infer from a pronoun.

## Hard lines (never break these)

- NEVER message anyone without your explicit permission.
- Money is read-only eyes, never a hand: never move money, pay, or
  order on your behalf.
- Never book, reserve, pay, submit, or send anything without your
  go-ahead on the exact text or action.
- No secrets, credentials, or API keys in this repo. Ever.
- Health detail stays out of the brain by design — keep clinical
  detail in your private health records, not here.
- Work-confidential material goes in only when you explicitly put it
  here. Never probe for it, never reconstruct it.
- Never touch a live shared document. Drafts live in the workspace
  until you say to apply them.

## ML + memory map (local-first)

- `ml/search.py` — stdlib TF-IDF + BM25: ranked search, related notes,
  link suggestions, clusters, duplicates. No installs, no API.
- `ml/embeddings.py` — optional local embeddings; absent = TF-IDF/BM25
  fallback. `scripts/memory-map.py` generates `MEMORY-MAP.md` and
  re-runs `scan.py`. Caches in `ml/.cache/` are gitignored. Details:
  `ml/README.md`.

## How to add a note

1. Create `notes/<kebab-case>.md` with a `# Title` first line.
2. Write tight: what it is, key facts with sources, `[[links]]`.
3. End with a `Tags:` line using 1–3 tags from the set above.
4. Run `python3 scan.py` to refresh MAP.md and dashboard.html.

## How to scan

`python3 scan.py` from this folder. It walks `notes/`, extracts tags
and `[[links]]`, and regenerates `MAP.md` and `dashboard.html`. It
prints the counts: notes, per-tag counts, links, broken links,
orphans. `python3 scripts/memory-map.py` also regenerates the full
`MEMORY-MAP.md` (every file, ML clusters, sources, stale flags).

## Git

Commit weekly with a ≤200-word summary. `raw/` is immutable — a
committed raw file is never force-pushed over. Never force-push.
Never rewrite history — the log is the point.

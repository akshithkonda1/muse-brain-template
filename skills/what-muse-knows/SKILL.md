# What Muse knows — skill

**Trigger:** "brain: knows <topic>" or "brain: what does Muse know about <topic>"

**Purpose:** answer, from the brain's own notes, what Muse knows about a
topic — and show the sources, so Akshith can check it. This is the
skill behind the "What Muse knows" view that appears after sign-in
(see `docs/login.md`).

## How it works

1. Run the ML search for the topic (`python3 -m ml.search "<topic>"`
   or the dashboard / app search). Ranked by BM25 + TF-IDF cosine —
   the same index the map uses.
2. Open the top notes. For each one, report:
   - the note's title and its one-line summary (the "what Muse knows"
     line — the first substantive paragraph of the note),
   - its tags and area (people, projects, money, goals, …),
   - its links in and out, and its cluster,
   - its **source trail**: every `Source:` line and `(per …)` line in
     the note, verbatim. If there is no source line, say so plainly
     and mark it `[source needed]` — never invent one.
3. Say what Muse does **not** know, too: if the top hit is thin, if
   the sources are missing, or if two notes disagree, name the gap
   instead of smoothing it over. A live tension stays visible.
4. Offer the next step: open the note, follow a link, or file a
   correction (`brain: learn <correction>`).

## Rules

- **Sources under every claim.** A claim without a source in the
  notes is reported as unsourced, not as fact.
- **Grounded reasoning.** Work from the complete, actual notes.
  Never fill a gap with a population average or an invented fact.
- **Privacy.** This skill reads the local brain only. It never
  uploads notes, never calls an API, and in the public template it
  only ever sees the generic example notes.
- The generated "What Muse knows" section of `MEMORY-MAP.md` is the
  offline version of this view — same data, regenerated by
  `python3 scripts/memory-map.py`.

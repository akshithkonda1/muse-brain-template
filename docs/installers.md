# Muse Brain as an app — Windows .exe and macOS .dmg

## What it is

The brain is still a folder of plain Markdown files. The apps are
**viewers over those files**, not replacements that lock data into a
database. Frontends stay separate and native per platform — they
share only the Markdown brain + ML + memory-map data layer:

- **macOS: native Swift / SwiftUI** (`macos/`) — reads the Markdown
  folder straight off disk, runs BM25 + TF-IDF search locally, draws
  the memory-map graph. Packaged as a `.dmg`.
- **Windows: React Native Windows** (`windows-app/`) — a native
  React Native Windows app (not Electron) that produces a real
  `.exe`. Ships the brain as a generated snapshot
  (`src/brain-data.json`, built from the Markdown files by
  `scripts/generate-brain-data.py`).
- **No installer needed:** `dashboard.html` — the polished UI
  (graph, BM25 search, note reader, tags/clusters, orphans/stale
  flags, dark/light), generated by `python3 scan.py` from
  `app/dashboard-template.html`. Open it directly in a browser — it
  works from `file://`, fully offline. `app/app.py` is a stdlib-only
  local server (no installs) that serves the folder and adds a live
  ML API: `/api/search`, `/api/related`, `/api/map`,
  `/api/notes/<stem>` (`python3 app/app.py`, or `app/run.sh` /
  `app/run.bat`).

| 1 | `muse-brain` (private) | Windows `.exe` | React Native Windows | GitHub Actions `windows-2022` |
| 2 | `muse-brain` (private) | macOS `.dmg` | Swift / SwiftUI + xcodebuild | GitHub Actions `macos-latest` |

| 4 | `muse-brain-template` (public, this repo) | macOS `.dmg` | Swift / SwiftUI + xcodebuild | GitHub Actions `macos-latest` |

The template installers (rows 3–4) contain only the generic example
notes in this repo. The private installers contain real personal
notes and are **never published**. Same code, same data layer —
different data, native UI per platform.

## Can I get real installers? (The honest answer)

Yes — but **not from a Linux machine**, and anyone who tells you
otherwise is faking it:

- A Windows `.exe` from React Native Windows needs Windows +
  Visual Studio 2022 (C++ workload) + Node. A macOS `.dmg` needs
  Xcode + `hdiutil`, which exist only on macOS. This Linux box has
  neither — so no installer can be produced or tested here. (An
  earlier PyInstaller spec was validated on Linux and then removed:
  the `.exe` is React Native Windows now, not PyInstaller.)
- The honest paths to real installers:
  1. **GitHub Actions (already wired):**
     `.github/workflows/build.yml` has two jobs — `build-windows`
     (Node 20 → `npm ci` → `react-native init-windows` →
     `run-windows --release` → `MuseBrain.exe` + DLLs) and
     `build-macos` (`xcodebuild` → `MuseBrain.app` → `hdiutil` →
     `MuseBrain.dmg`). It runs on every push to `main` and on demand
     (Actions tab → "Build installers" → Run workflow). Artifacts:
     `MuseBrain-windows-exe` and `MuseBrain-macos-dmg`. The CI
     smoke-tests each one before upload (starts the app, checks it
     stays alive).
  2. **By hand on the native machine:**
     - Windows: see `windows-app/README.md`
       (`npm ci` → `npm run brain-data` →
       `react-native init-windows` → `run-windows --release` →
       `windows\x64\Release\MuseBrain\MuseBrain.exe`).
     - Mac: see `macos/README.md`
       (`xcodebuild … build`, then stage + `hdiutil create` →
       `MuseBrain.dmg`).

## How the installers work

- **macOS:** open the `.dmg`, drag `MuseBrain.app` to Applications
  (or run it from the image). The app looks for the brain folder in
  this order: your saved choice, a `Brain/` folder next to the
  `.app`, `~/MuseBrain`, `~/Documents/MuseBrain` — otherwise it asks
  you to choose one. The `.dmg` ships a `Brain/` copy of the repo
  next to the app, so it works out of the box.
- **Windows:** unzip the artifact and run `MuseBrain.exe` (ship the
  whole `MuseBrain` folder — the `.exe` needs its DLLs next to it).
  The brain is the snapshot bundled at build time; re-run
  `npm run brain-data` and rebuild after editing notes. (A live
  "choose brain folder" picker is a follow-up — it needs a WinRT
  native bridge; see `windows-app/README.md`.)

Notes never leave the machine. No cloud, no account, no server, no
API keys. Generated caches/embeddings stay gitignored and are never
shipped.

## Signing — what still needs you

Both installers are **unsigned**:

- Windows SmartScreen will warn on first run ("Run anyway"). Proper
  signing needs a code-signing certificate (or Azure Trusted
  Signing).
- macOS Gatekeeper will block the first open — right-click the app
  → Open (or System Settings → Privacy & Security → Open Anyway).
  The `.dmg` is built on `macos-latest` (Apple Silicon); Intel Macs
  need Rosetta 2. Proper signing/notarization needs an Apple
  Developer ID (Developer ID Application + notarization, $99/yr).
- Until then, the unsigned builds work — they just warn once.

## Privacy

This is the **public template**. Its `.exe`, `.dmg`, packaged
folder, and Actions artifacts contain only the generic example
notes in this repo — no personal data. The private brain
(`muse-brain`) is a separate repo; its installers contain real
personal notes and are never published.
